# 服装库 + 姿势库 —— 设计稿 v1

> 目标版本 **v5.1.0**（当前 v5.0.31）
> 用户口径（2026-11-05 17:0x 四项拍板）：
> ① 服装库 **全局一套 + 角色预设优先**；② 首版 **9 类 × 约 10 套 ≈ 90 套**；
> ③ 新增姿势 **全部 manual_only，不进随机池**；④ **32 条瑜伽 + 8 条通用伸展，全 L0–L1，不 drop 服装字段**。

---

## 一、现状（动手前的基线，读完代码的结论）

| 项 | 现状 | 对本次的影响 |
|---|---|---|
| 左列页签 | `_TABS = ["weights","chars","scenes","art","near"]`（JS 541 行） | 加两个页签要同步 `_TABS` / `rememberUi` / 冒烟用例 |
| 场景数据 | 一份 `/scenes`（`scenes_payload()` 组装，374 条：sfw100 / near60 / nsfw71 / pose40 / art103） | 姿势页签 = 同一份数据换个过滤，无需新接口 |
| 姿势场景 | `group=pose`，40 条，目前只是「🎬 场景搭配」页里的一个筛选按钮 | 升一级页签后，场景页要**移除**这条筛选，并把 pose 从该页列表里排掉 |
| 随机场景 | `scene_pick` 开关 → `n_canon` 锁档抽；`manual_only` 默认不进池，只有权重 3.0 才补进来 | 新姿势标 `manual_only` → 随机分布**零漂移** |
| 角色服装预设 | `presets/character_outfits.json`，`{role:{enabled,list}}` | 服装库可复用同一套条目结构（`id/zh/level/tags/fields/drop/verified/note`） |
| 引擎合并点 | 单人：`anima_v4_rules.py` 4838 附近；双人：`duo_outfit_text()`（3518） | 两处都要改成「角色预设 > 服装库 > 随机」 |
| 服装词汇量 | outfit70 / top40 / bottom39 / socks81 / shoes24 / accessory13 | 套装细节（`white off-shoulder sweater`）必须走 `tags` extra 通道 |
| 姿势词汇量 | `pose_base` 只有 28 项、`pose_risque` 22 项 —— **没有瑜伽词** | 瑜伽体式只能写进 `extra`，`pose_base` 取最接近的近似值 |

## 二、功能一：服装库（9 类 × 10 套 = 90 套）

### 2.1 数据文件

`presets/outfit_library.json`（**构建产物 + 用户可编辑**）：

```jsonc
{
  "_meta": {
    "schema": "anima-v5/outfit-library@1",
    "updated_at": "…",
    "count": 90,
    "active": "ol_knit_pleated",              // 启用中的那一套；"" = 关闭
    "categories": [
      {"id": "casual", "zh": "日常休闲", "desc": "…"},
      …共 9 类
    ]
  },
  "outfits": [
    {"id":"ol_knit_pleated","zh":"露肩针织 · 百褶","cat":"casual","level":0,
     "tags":["white off-shoulder sweater","black pleated skirt","brown loafers"],
     "fields":{"outfit":"sweater and skirt","top":"off-shoulder sweater",
                "bottom":"pleated skirt","shoes":"loafers","cloth_color":"white"},
     "drop":[…13 个服装字段…],"note":"…","verified":false}
  ]
}
```

- `level` **由 `tools/build_outfit_library.py` 派生**（= max(各 fields 的 `option_level`，各 tag 的 `tag_level`)），不手写。
- `drop` 缺省 = `OUTFIT_FIELDS` 全 13 项（与角色预设同口径）。
- 分类九类：

| cat | 中文 | 条数 | 档位 |
|---|---|---|---|
| casual | 日常休闲 | 10 | 0 |
| school | 校园制服 | 10 | 0–1 |
| office | 职业通勤 | 10 | 0–1 |
| traditional | 传统服饰 | 10 | 0–1 |
| formal | 礼服派对 | 10 | 0–1 |
| home | 居家睡衣 | 10 | 0–1 |
| swim | 泳装内衣 | 10 | 1–2 |
| combat | 战斗机能 | 10 | 0–1 |
| cosplay | 主题扮演 | 10 | 0–1 |

### 2.2 后端

| 层 | 改动 |
|---|---|
| `anima_v4_store.py` | `LIBRARY_FILE` / `library_load()` / `list_library()` / `save_library_outfit()` / `delete_library_outfit()` / `set_library_active()`；复用 `_clean_outfit()`，多校验 `cat` 必须在 `_meta.categories` 里 |
| `__init__.py` | `GET /outfit-library`、`POST /outfit-library/save|delete|enable`；**写操作一律 `R.clear_cache()`**（与 `/outfits` 同纪律） |
| `anima_v4_rules.py` | `library_data()`（`_CACHE`）/ `library_active()` / `library_outfit(lv)` → `(extras, drops, sets)`，形状与 `outfit_for()` 完全一致；`effective_outfit(role, lv)` = 角色预设非空则用它，否则用服装库 |

**优先级落点**：

```
单人：effective_outfit(role, lv)          # 角色预设 > 服装库
双人：duo_outfit_text() 内部对每个角色用 effective_outfit()
       → 两人各写一句「X wears …」；两人都没预设时共用服装库那套
```

⚠️ 服装库**不受 `appearance_follow` 管辖**（与 v5.0.13 角色预设同一条口径）。
⚠️ 未启用（`active=""`）时 `library_outfit()` 返回空三元组 → rng 消耗不变，**零影响**。

### 2.3 前端

- `_TABS` 改为 `["weights","chars","outfits","scenes","pose","art","near"]`。
- 新页签 `👗 服装库`：
  - 顶部分类条（9 个按钮 + 「全部」），再下面搜索框（多词 AND）；
  - 卡片：`中文名` + 分类徽标 + 档位徽标 + tags 数；点卡片 = **启用**（单选）；
  - 已启用卡片高亮 + 顶部一条「当前启用：X ｜ 关闭（回到随机）」；
  - 展开卡片可看 tags / fields / drop 明细（复用场景卡的折叠交互）。
- 服装库与角色预设的关系在页首用一行说明：`角色启用了自己的预设时优先用角色的`。

## 三、功能二：姿势库（40 → 80 条）

### 3.1 页签拆分

| 页签 | 数据过滤 | 页面元素 |
|---|---|---|
| 🎬 场景搭配 | `!manual && group !== "pose"`（sfw + nsfw） | 删掉「全部 / 🧎 姿势场景」筛选条；保留随机开关、档位分组、搜索、收藏 |
| 🧘 姿势库（新） | `group === "pose"`（含 manual_only 的新条目） | 分类条（基础姿势 / 瑜伽 / 伸展）、搜索、收藏；**不显示随机开关**（姿势不进随机池） |

- `renderScenes()` 增加 `onlyPose` 分支（照 `onlyArt` 的写法），`repaintScenePage` 同步。
- 套用机制不变：写 `fields.n_canon=3.0` + `options.n_canon={id:3.0}` → 随工作流保存、零控件迁移。

### 3.2 新增 40 条（全部 `manual_only=true`、`group=pose`、`count_lock="1girl, solo"`）

- **瑜伽 32 条**：山式 / 树式 / 战士一 / 战士二 / 战士三 / 三角式 / 侧角式 / 半月式 / 鹰式 / 舞王式 /
  下犬式 / 上犬式 / 眼镜蛇式 / 蝗虫式 / 猫牛式 / 婴儿式 / 鸽子式 / 束角式 / 莲花坐 / 英雄坐 /
  桥式 / 船式 / 骆驼式 / 犁式 / 肩倒立 / 头倒立 / 站立前屈 / 坐姿前屈 / 侧弯 / 扭转 / 平板支撑 / 侧板
- **通用伸展 8 条**：肩颈伸展 / 弓步伸展 / 髋部开合 / 体侧拉伸 / 背部门框伸展 / 小腿靠墙伸展 /
  跪姿后仰 / 双臂上举伸展

写作纪律（照 §1 的坑）：

| 约束 | 做法 |
|---|---|
| `pose_base` 词表只有 28 项 | 取近似值（下犬/猫牛 → `all fours`，婴儿/骆驼 → `kneeling`，桥/犁/肩倒立 → `on back`，树式/战士三 → `standing on one leg`）；体式名放 `extra` |
| 体式名不在词库 | 全部走 `extra`（`downward dog` / `warrior pose` / `tree pose` …），逐标签过档位闸门 |
| 手部崩坏 | `drop_fields` 加 `arms_hands` + `action`（否则随机抽到 `waving` / `reading` 会毁掉体式）；手的位置写进 `extra` |
| 服装不准被锁死 | **不写服装字段、不加服装词**（`yoga pants` 属 `bottom` 选项，不进 tags 也不进 extra —— 服装交给角色预设 / 服装库） |
| 档位 | 全 L0–L1；`level` 由 `build_scenes.py` 派生，不手写 |
| 画幅 | 走 `build_scene_aspects.py` 派生（瑜伽多为竖构图全身/半身） |

### 3.3 测试联动

- `tests/check_v3_scenes.py`：`pose >= 80`；新增断言「新增 40 条全部 `manual_only`」「瑜伽主题都是 `姿势·瑜伽`」「不写服装字段/服装词」「全部 L0–L1」。
- `tests/av3_ui_smoke.mjs`：页签数 5 → 7、索引断言重排、新增「服装库页能渲染 90 张卡」「姿势页只列 pose」。
- `tests/run_all.py`：新增 `check_v3_outfitlib.py`。

## 五、不做的事（本版明确排除）

- 不做服装库的收藏（三份收藏文件已经够多；先看使用频率）
- 不加 `pose_pick` 节点控件（避免工作流迁移；姿势手动套用即可）
- 不做服装库的「批量导入角色服装预设」（后续版本再议）

## 六、实施记录（v5.1.0 落地后的偏差说明）

| 设计稿写的 | 实际做的 | 原因 |
|---|---|---|
| 瑜伽 32 条含「头倒立」 | **换成「宽角前屈」** | `pose_base` 28 个词里没有任何倒立体式，头倒立只能靠 `extra` 硬写，首轮实测模型直接画成趴地。宁缺毋滥 |
| 服装库档位纯派生 | 加了 `min_level` 人工下限表 | `grade_nsfw` 判 `bikini` / `naked apron` / `garter straps` / `thigh boots` 全是 0 档，只看派生会让内衣泳装漏进 SFW |
| 页面「▶ 展开看明细」 | 保留，且**卡片本体点击 = 启用** | 与角色库「点卡片即采用」一致；箭头单独 `stopPropagation` 管折叠 |
| 未提 | `loadScenes()` 回调漏了 `pose` 分支 | 前端冒烟抓到：数据回来了却不重绘，界面永远停在「正在加载姿势库…」。本质是「新页签要补进所有 `renderScenes()` 判断」，共 4 处 |
| 未提 | 下犬式改写两轮 | 首版 `head down / face down` 会被画成「头贴地」；改成 `head hangs free … without touching the floor` + `toes on mat` 才成立 |

**验收落盘**：`output/图片/姿势库验收/` —— 下犬式（16:9 一轮 + 竖幅三轮）、莲花坐、桥式。
