## 〇、一句话结论

把服装库从「手动钉一套」升级成「**每次运行从指定子池里抽一套**」，复用场景侧 v6.7.0 勾选池
已验证的三条纪律（独立 rng / seed 决定复现 / 池子进指纹），**默认关闭时逐字节零漂移**。

真正的难点不是抽签，是三件事：

| # | 难点 | 不处理的后果 |
|---|---|---|
| ① | 一次 draw 内**三处调用点必须拿到同一套** | 单人正文穿 A、双人句穿 B；标签重复/服装冲突 |
| ② | 泳装硬禁只管字段池，**管不到 extras** | 非泳装场景抽出 bikini（不是概率问题，是必然） |
| ③ | 档位闸门是"整套不生效"而非"换一套" | 抽到 L3 套 + sfw 档 → 静默无服装，用户以为库坏了 |

## 一、目标 / 非目标

| 类型 | 内容 |
|---|---|
| **目标** | ① 每次运行从「分类 × 档位」子池里抽一套，seed 固定则复现；② 与「钉一套」互斥，UI 只有两个入口；③ 右栏「已套用」显示这是开着的一条随机通道（v6.22.0 那套行的第 5 类）；④ 关闭时零漂移 |

## 二、现状链路（读完代码的基线）

| 位置 | 现状 | 对本次的影响 |
|---|---|---|
| `anima_v4_rules.py:3961` `library_active_item()` | 读 `_meta.active` → 从 `library_data()`（进程级 `_CACHE`）里找那一套 | 池化不能改这里（多调用点会各抽一套 → 难点①） |
| `:4052` `library_outfit(lv)` | `_outfit_triplet(active_item, lv)` + `apply_library_overrides()` 叠袜鞋覆盖 | 池化要能在**不破坏覆盖逻辑**的前提下换 item |
| `:3849` `_outfit_triplet(item, lv)` | 条目 → `(extras, drops, sets)`；`lv < item.level` 直接返回空三元组 | 池化必须**先按档位过滤池子**，否则抽到高套 = 整套消失 |
| `:4066` `effective_outfit(role, lv, scene_has_outfit)` | 角色预设 > 场景让路 > 服装库 | 池化挂在「服装库」这一档，前两档语义不动 |
| `:4229` / `:4256` / `:5910` | 三个调用点：`duo_outfit_text` / `duo_feat_text`（仅为排除重复标签）/ 单人 body 注入 | **三处必须同参**，否则双人/单人 split-brain（难点①的现场） |
| `__init__.py:735` `/outfit-library/enable` | 写 `_meta.active` 后 `R.clear_cache()` | 新池化路由照抄这条纪律 |
| `anima_v4_store.py:1253` `_library_write()` | 整份写回，`active=None` 时沿用旧值，其余 meta 键原样保留 | 加 `pool` 键不会冲掉 `overrides` / `scene_override` |
| `nodes.py:102` `_global_state_fingerprint()` | 拼 `outfit_library.json` 的 `mtime_ns+size` | **池子改动自动破节点缓存**，不用额外接线 |
| `anima_v4_outfit_style.py:667` `style_bans()` | 非 `swim` 锚点禁整套泳装，但只作用于字段候选池 | 池化走 extras → 绕过硬禁（难点②） |

> **注：为什么池子存盘而不加节点控件**
> `scene_pick` 存控件是因为它必须与工作流一起保存（同一个工作流两种场景开关状态要能共存）。
> 服装库的 `active` / `overrides` / `scene_override` 全部是**服务端全局态**，`outfit_pick` 属于同一族
> （"我这一阵子穿什么风格"是用户级偏好，不是工作流级参数）。跟着 `active` 走还免了
> `INPUT_TYPES["optional"]` 尾部追加的契约风险。

## 三、数据契约

`presets/outfit_library.json` 的 `_meta` 新增一个键（缺省 = 关闭，旧文件零迁移）：

```json
"_meta": {
  "pool": {
    "on": false,
    "cats": [],
    "max_level": 4,
    "ids": [],
    "_last": ""
  }
}
```

| 字段 | 类型 | 语义 | 缺省 |
|---|---|---|---|
| `on` | bool | 池化总开关。`true` 时 `active` 必须为空（互斥，见 §6） | `false` |
| `cats` | string[] | 参与抽签的分类 id（`casual`/`school`/…）。**空 = 全部分类** | `[]` |
| `max_level` | int | 池内档位上限（0–4）。`4` = 不额外限制；实际仍受当前 NSFW 档位闸门约束 | `4` |
| `ids` | string[] | 逐套池（V2 用）。**非空时忽略 `cats`** | `[]` |
| `_last` | string | 上一轮实际抽到的套 id（只写不读，供面板显示"上次抽到：XX"） | `""` |

**为什么 `max_level` 与节点档位并存**：节点档位是"这张图能到什么程度"，`max_level` 是"这套衣服的上限"。
两者取交集。典型用法：节点档位 extreme，但 `max_level=0` → 极端图里也穿日常装（比现在只能手钉一套灵活）。

## 四、引擎改动（`anima_v4_rules.py`）

### 4.1 新增 `library_pool()` —— 读池子状态

```python
# ⚠️ normalize_cat 的真源在 anima_v4_store.py:1172（分类别名归一层），
#    rules 里一律 `from . import anima_v4_store as _S` 后调 `_S.normalize_cat()`，
#    不要在 rules 里再写一份 —— 两份归一会漂移。
def library_pool() -> dict:
    """_meta.pool 的规整视图。缺省 / 脏数据一律回落到"关闭"。"""
    meta = library_data().get("meta") or {}
    p = meta.get("pool")
    if not isinstance(p, dict):
        return {"on": False, "cats": [], "max_level": 4, "ids": [], "_last": ""}
    return {
        "on": bool(p.get("on")),
        "cats": [_S.normalize_cat(c) for c in (p.get("cats") or []) if str(c).strip()],
        "max_level": int(p.get("max_level") if p.get("max_level") is not None else 4),
        "ids": [str(x).strip() for x in (p.get("ids") or []) if str(x).strip()],
        "_last": str(p.get("_last") or ""),
    }
```

> **必须走 `library_data()`（带 `_CACHE`）而不是 store 直读**：items 与 pool 必须来自**同一份快照**，
> 否则"池子里有这套、items 里还没有"会抽到空。写池子的路由负责 `R.clear_cache()`。

### 4.2 新增 `resolve_library_pick(lv, seed, st, outfit_style)` —— 一次 draw 只算一次

```python
_SWIM_TAG_WORDS = ("bikini", "swimsuit", "one-piece", "swim brief", "monokini")

def resolve_library_pick(lv, seed, st=None, outfit_style="随机"):
    """本轮该用哪一套。返回 {"on": bool, "item": dict, "why": str}。

    on=False → 调用方走原路径（library_active_item()），零漂移。
    on=True  → item 可能是空 dict（= 池内无可用套，**整套让路**，不许回落 active）。
    """
    pool = library_pool()
    if not pool["on"]:
        return {"on": False, "item": None, "why": ""}

    items = library_data().get("items") or []
    cap = min(int(pool["max_level"]), 4)
    drop_swim = _pool_anchor_not_swim(st, outfit_style)   # 见 §4.3
    cand, why = [], []
    for o in items:
        if not isinstance(o, dict): continue
        if int(o.get("level") or 0) > min(lv, cap):
            continue                                       # 档位闸门前置（难点③）
        if pool["ids"]:
            if str(o.get("id")) not in pool["ids"]: continue
        elif pool["cats"] and _S.normalize_cat(o.get("cat")) not in pool["cats"]:
            continue
        if drop_swim and _is_swim_suit(o):                  # 难点②
            continue
        cand.append(o)

    if not cand:
        why = ("服装池：该档位/分类无可用套（lv=%d cap=%d）→ 本次不套用服装" % (lv, cap))
        if drop_swim:
            why += "；已剔除泳装套（当前锚点非泳装）"
        return {"on": True, "item": {}, "why": why}

    # 独立 rng：**绝不用 pass_rng**（主序列零漂移的硬要求，同 v6.7.0 勾选池）
    try:
        rng = random.Random(int(seed)) if (seed is not None and int(seed) >= 0) else random.Random()
    except (TypeError, ValueError):
        rng = random.Random()
    item = cand[rng.randrange(len(cand))]
    return {"on": True, "item": item, "why": "服装池 %d 套 → 本次抽到「%s」"
                                            % (len(cand), item.get("zh") or item.get("id"))}
```

### 4.3 泳装交叉（难点②的解法）

```python
def _pool_anchor_not_swim(st, outfit_style) -> bool:
    """当前锚点是否"非泳装"。拿不到锚点时**按非泳装处理**（保守）。"""
    if not st: return True
    try:
        from . import anima_v4_outfit_style as OS
        anchor, _src = OS.anchor_of(st, outfit_style or "随机")
        return anchor != "swim"
    except Exception:
        return True

def _is_swim_suit(item) -> bool:
    """判**tags**，不判 cat —— swim 分类里有情趣内衣（L3 两套），按 cat 会误伤。"""
    blob = " ".join(str(t).lower() for t in (item.get("tags") or []))
    return any(w in blob for w in _SWIM_TAG_WORDS)
```

**已知取舍**：这条排除是"锚点未知时保守剔除"，代价是 `swim` 分类在随机场景里被大幅稀释
（只剩锚点明确是 beach/poolside/onsen 时才会抽到）。**不做**"抽到泳装就重抽"—— 重抽会引入
不确定的 rng 次数，破坏可复现性。

### 4.4 改签名（三处传参，难点①的解法）

| 函数 | 改动 | 兼容性 |
|---|---|---|
| `library_outfit(lv=99)` | → `library_outfit(lv=99, item=None)`；`item is None` = 用 `library_active_item()`（旧行为），`item={}` = 明确"本轮没有套" | 默认值等于旧行为；**袜鞋覆盖只在这一处叠加**，不复制第二份 |
| `effective_outfit(role, lv, scene_has_outfit=False)` | → 末尾加 `pick=None`；`pick["on"]` 为真时 `library_outfit(lv, item=pick["item"])` | 默认 `None` = 旧路径；现有 70 项断言不受影响 |

```python
def library_outfit(lv=99, item=None):
    tri = _outfit_triplet(library_active_item() if item is None else item, lv)
    if not tri[0] and not tri[1]:
        return tri                       # 空三元组不叠袜鞋（"整套闸门"语义，不变）
    return apply_library_overrides(*tri)


def effective_outfit(role_trigger, lv=99, scene_has_outfit=False, pick=None):
    item = outfit_item(role_trigger)
    if item:
        return _outfit_triplet(item, lv)              # ① 角色预设（最高，不变）
    if scene_has_outfit and not library_scene_override():
        return [], [], {}                             # ② 场景让路（不变）
    if pick and pick.get("on"):
        return library_outfit(lv, item=pick.get("item") or {})   # ③' 池化（空则整套让路）
    return library_outfit(lv)                         # ③ 原有单套路径
```

**三个调用点全部改成传同一个 `pick`**：

| 调用点 | 位置 | 传参方式 |
|---|---|---|
| `duo_outfit_text(triggers, lv, scene_has_outfit)` | `:4207` → `:4229` | 加 `pick=None` 形参，draw 里传 `_pick` |
| `duo_feat_text(triggers, seed, lv, scene_has_outfit)` | `:4238` → `:4256` | 同上（只为排除标签，也必须同套） |
| 单人 body 注入 | `:5910` | 直接传 `_pick` |

### 4.5 draw() 内的解析时机

```
draw()
 ├─ collect 阶段（抽 place / 场景 / 人物 ...）
 ├─ ★ _pick = resolve_library_pick(lv, seed, st, outfit_style)
 │      必须在 collect **之后**：泳装判据要 st["place"]；_anchor_st(st) 要 n_canon 已落
 ├─ 双人句 duo_outfit_text(..., pick=_pick)      ← 5685
 ├─ 双人特征 duo_feat_text(..., pick=_pick)      ← 5719
 ├─ 单人 body 注入 effective_outfit(..., pick=_pick) ← 5910
 └─ if _pick["on"] and _pick["why"]: notes.append(_pick["why"])
```

> **为什么不在 draw 开头解析**：place 还没抽，泳装判据必然失效 —— 这正是 v6.16.0 修过的那个坑
> （"服装锚点算的是随机预抽的 place"）。放在 collect 之后，`_anchor_st(st)` 与 `anchor_of(st)`
> 都拿得到真值。

### 4.6 `_last` 回写（可选，推荐做）

抽完把 `_pick["item"]["id"]` 写进 `_meta.pool._last`。**只写一次、失败不影响出图**（try/except 包住）。
价值：面板能显示"上次抽到「图书馆制服」"，解决"随机抽了我看不见"的原始痛点。
⚠️ 写盘会让指纹变 → seed>=0 时下一张会重跑。**因此只在 `on` 为真且 id 变化时写**，且
`IS_CHANGED` 里对 `pool` 只取 `on/cats/max_level/ids`，**不含 `_last`**（见 §5）。

## 五、指纹（`nodes.py`）

`outfit_library.json` 已在 `_global_state_fingerprint()` 的文件列表里（`nodes.py:126`），
所以 `_meta.pool` 改动天然破缓存。但 `_last` 每次 draw 都写 → 若直接靠文件 mtime，
**每张图都会破缓存**（等于 seed 固定也重抽，可复现性崩塌）。

```python
# _global_state_fingerprint() 内，文件指纹之后追加：
f"|opool:{_pool_fp()}"   # on|cats|max_level|ids —— 只读 meta，不读 _last
```

`_pool_fp()` 走 store 读盘（轻量，只取 4 个键），异常时返回 `""`。

## 六、路由（`__init__.py`）

| 路由 | 方法 | 入参 | 行为 |
|---|---|---|---|
| `/outfit-library/pool` | POST | `{on, cats, max_level, ids}` | 写 `_meta.pool`；`on=true` 时**清空 `active`**（互斥）；写后 `R.clear_cache()`；返回 `{ok, pool, library}` |

现有 `/outfit-library/enable` 反向互斥：`id` 非空时把 `_meta.pool.on` 置 `false`（钉一套 = 退出池化）。

`library_payload()`（`anima_v4_store.py:1201`，返回 `schema/updated_at/active/overrides/scene_override/categories/count/counts/outfits`）
增加一项 —— 前端拿它直接渲染状态条，不必自己再过一遍筛选：

```python
"pool": {
    "on": bool, "cats": [...], "max_level": int, "ids": [...], "_last": str,
    "count": n,        # 当前 cats/max_level 过滤后的候选条数（不含档位过滤，档位是运行期的）
},
```

`set_library_pool()` 放在 `anima_v4_store.py`，与 `set_library_active():1308` 并列，同样做
`cats` 校验（`normalize_cat` 归一后必须在 `_meta.categories` 里）与 `max_level` 钳位 0–4；
`on=True` 时同一次 `_library_write(..., active="")` 把 active 清空（互斥只写一次盘，避免中间态）。

|---|---|
| 1 | `pool.on=false` 时 `resolve_library_pick` 返回 `on=False`，且**不消耗任何 rng**、不读 items |
| 2 | 一次 draw 内三处调用点**共用同一个 `pick` 对象**（禁止在任何一处重新 resolve） |
| 3 | `pick.on=true` 且 `item={}` 时**绝不回落** `library_active_item()`（否则池空时偷偷穿上一套） |
| 4 | 抽签只按 `level <= min(lv, max_level)` 过滤，**不做自动抬档**（服装不是画面主体，抬档风险高于收益） |
| 5 | 池内无可用套 → 整套让路 + `notes` 写明原因，不静默 |
| 6 | 泳装排除判 **tags** 不判 **cat**（swim 分类含情趣内衣） |
| 7 | 抽签 rng 独立于 `pass_rng`；`seed>=0` 同 seed 同套，`seed<0` 每次换 |
| 8 | 角色预设 / 场景让路 / 袜鞋覆盖 三条既有优先级**一字不动** |
| 9 | 写池子后必须 `R.clear_cache()`（与 `/enable` 同纪律） |
| 10 | `_meta.overrides` / `scene_override` / `categories` 在写盘时原样保留（`_library_write` 整份重写，必须显式带上） |
| 11 | `pool` 进 `library_payload()`；`_last` **不进指纹** |
| 12 | 池化与 `active` 互斥：任一方向切换时另一侧必须被清空，不允许"钉着一套又开着池" |

## 九、零漂移论证

| 场景 | 路径 |
|---|---|
| `pool.on=false`（默认，旧文件无此键） | `library_pool()` 返回 `on=False` → `pick={"on":False}` → `effective_outfit` 走原 `library_outfit()`；`_outfit_triplet` / `apply_library_overrides` 未改 → 同 seed 逐字节一致 |
| `pool.on=true` | 只改"用哪一套"，三处优先级与合并顺序不变；`pass_rng` 抽取序列不受影响（独立 rng） |
| 指纹 | 关闭态 `_pool_fp()` 恒为 `on:0|...`，与未加此字段前等价（指纹变了但恒定，缓存命中行为不变） |

**验证方法**：`pool.on=false` 时对 5 个 seed × 3 档位的 `draw()` 正文做 sha256，改前改后逐字节比对。
