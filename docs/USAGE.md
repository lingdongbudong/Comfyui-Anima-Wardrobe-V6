## 一、安装与配置

### 1.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| ComfyUI | 任意近期版本 | 只用 `nodes` / `server` / `folder_paths` 三处公开接口 |
| Python | 3.10+ | 用 ComfyUI 自带的那套即可，**不要**另建虚拟环境 |
| 第三方依赖 | **零** | 纯标准库 + 原生前端 JS，没有 `requirements.txt` |
| 模型 | Anima-2.9B / 29B | 只有真正出图才需要；验证安装、跑测试都不需要 |
| 磁盘 | 约 40 MB | 其中 29 MB 是 2432 张角色缩略图；纯代码 + 数据约 11 MB |

### 1.2 两种安装方式

**方式 A · git clone**（推荐，便于以后 `git pull`）

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/lingdongbudong/Comfyui-Anima-Wardrobe-V6.git
```

**方式 B · 下载 ZIP**

在仓库页面点 `Code → Download ZIP`，解压后把整个文件夹放进 `ComfyUI/custom_nodes/`，
**目录名保持 `Comfyui-Anima-Wardrobe-V6`**（改名会让 `tests/_boot.py` 里的包名对不上）。

两种方式都**不需要**装依赖、不需要改配置、不需要动工作流。

### 1.3 三步验证安装

```bash
# ① 看节点是否注册（启动 ComfyUI 后，控制台应出现分类 AnimaWardrobeV6）
#    或者直接查路由：
curl --noproxy '*' http://127.0.0.1:8188/anima-wardrobe-v6/health
```

② 画布上双击空白处搜「Anima」，能看到四个节点：
`Anima 提示词随机生成（V6）` / `分级审查` / `拼接台` / `检查与修复`。

③ 把「随机生成（V6）」拖进画布，**不接任何东西**，直接 `Queue`。
`text` 输出应是一串非空标签，`report` 里全是 ✅ —— 这一步不加载模型、不出图，
是判断"插件本身装好没有"的最短路径。

> ⚠️ 只验证①②不验证③的话，最容易漏掉的情况是「节点注册了但词库没读到」——
> 那种情况下节点是灰的、一点就报 `KeyError`。

### 1.4 建议的初始配置

| 场景 | 怎么设 |
|---|---|
| 只想先看看效果 | 档位 `sfw`，其余全默认，`seed = -1` |
| 接了出图链路 | 档位按需，`seed = -1`；要复现时改成具体正整数 |
| 批量出图 | `seed = -1` + 关掉「每次运行自动随机」，用同一个工作流连跑 |
| 只想要某几条内容 | 面板里点选项、给 `3.0`（见 [五、三层权重](#五三层权重)） |

### 1.5 数据文件：哪些随仓库、哪些本机生成

| 文件 | 随仓库 | 说明 |
|---|---|---|
| `presets/anima_v4_pools.json` | ✅ | 词库（零漂移导出物），**改它没用，真源是 HTML** |
| `presets/anima_v4_characters.json` | ✅ | 角色库 2432 位，只读 |
| `presets/anima_v4_scenes.json` | ✅ | 场景搭配 524 条 |
| `presets/outfit_library.json` | ✅ | 服装库 135 套 |
| `presets/character_outfits.json` | ✅ | 角色 → 服装预设映射 |
| `presets/user_*.json`（5 份） | ✅ **空模板** | 运行后变成你的收藏 / 自定义角色 / 命名预设 —— **提交前先还原** |
| `presets/thumbs/` | ✅ | 2432 张角色缩略图（160×160 webp / 29 MB），**随仓库分发**，与角色库 1:1 |
| `presets/user_thumbs/` | ✅ | 9 张作者自定义角色的预览图（示例）；你自己的会覆盖同名文件 |
| `tools/.cache_*/` | ❌ | 建库缓存，可重建 |

**关于缩略图的来源**：2432 张**全部由作者本地用 Anima 出图裁切生成**
（生成流程见 `tools/make_new_char_thumbs.py`：非白包围盒 → 取上部居中裁方 → 缩放 160 → webp）。
与角色库一一对应，**仅作面板里的角色识别对照**。

⚠️ 仓库里另带一个 `tools/fetch_character_thumbs.py`，那是**给不想自己出图的人**准备的
备用路径（从 safebooru 镜像抓公开预览图）。仓库自带的这批**不是**它抓的。

⚠️ 若你浅克隆（`--depth`）或手动删了 `presets/thumbs/`，面板**不会报错**，
角色卡退化成首字母色块，功能照常。想重抓或换成自己跑的图：

```bash
# ⚠️ 必须用 ComfyUI 内嵌的 Python —— 转 webp 依赖 Pillow，系统 Python 通常没有
<ComfyUI>/python_embeded/python.exe tools/fetch_character_thumbs.py
# 可中断可续跑，每次跑会先自愈清掉尺寸过小的坏图
```

### 1.6 升级与卸载

**升级**：`git pull` 即可。唯一要守的是一条 —— 你的个人数据在
`presets/user_*.json`，若那五份有本地改动，先 `git stash` 或先备份再拉。

**卸载**：删掉整个目录，重启 ComfyUI。插件不写注册表、不在仓库外落任何文件
（唯一例外是 `/roll` 报错时写的 `_roll_error.log`，也在插件目录内）。

## 四、NSFW 分级标准（核心）

沿用造型台已有的 **0–4 五级标度**，与 `AnimaNSFWGrader` 逐字对齐（有对拍测试钉住），
另加一个 `不限`。数值越大越露骨，低档**先从候选池里排除**，不是抽完再筛。

| 档 | key | 判定口径（画面里能看到什么） | 放开的内容 |
|---|---|---|---|
| **0** | `sfw` | 无任何暴露向内容 | ①–⑩ 段；⑥服装 / ⑦姿势 限安全子集 |
| **1** | `suggestive` | 有暗示但不露 | 微距泳装 · 高开叉 · 镂空裁剪 · 露肩 · 短裙 · 内衣轮廓 · 湿度质感 |
| **2** | `explicit` | 明显裸露或透视 | 全裸 / 上裸 / 透视真露 / 乳头 / 私处 / 内衣外露 / 半脱 · 法典场景 c1–c4、c7 |
| **3** | `hardcore` | 性行为 / 性道具 / 体液 / 束缚调教 | ⑫体位与性行为段 + ⑬特殊主题段 · 法典场景 c5、c6、c8、c10–c12、c14 |
| **4** | `extreme` | 群体 · 极端插入扩张 · 极端拘束装置 · 极限体液 | 群体多人 / 双管齐下 / 悬挂拘束 / 过量精液 等分类 · 法典场景 c9、c13 |
| — | `any` | 不设上限 | 全库开放，等价于源脚本的「NSFW 模式」 |

| 段落 | 0 全年龄 | 1 擦边 | 2 成人 | 3 过激 | 4 极端 |

| ①–⑤ 主体 / 外貌 / 妆容 | ● | ● | ● | ● | ● |

> ⚠️ 关于「擦边档」：`透视装 see-through` 本身判 **2 级**，所以 1 档的露出主要来自
> ⑥ 段的微距泳装 / 仅围裙 / 浴巾 / 露肩 / 湿身，以及 ⑨ 段的更衣室 / 浴室场景。
> 这是刻意收的口径，不是遗漏。

### 档位是怎么算出来的

三层叠加，顺序不能反：

```
最终档位 = max(判定表逐标签结果, 所在段的段下限, 逐选项上抬表)   →   再经人工校准表下调
```

- **判定表**：`anima_v4_nsfw.py`，从造型台 `wardrobe_rules.py` **逐字切片**而来，
  33 个常量 + 函数全部源码级对拍（`tests/check_nsfw_parity.py`）。
- **段下限**：`anima_v4_overrides.SECTION_FLOOR`。⑪⑫⑬⑭ 是 NSFW 专用段，
  段内任何内容都不应出现在低档。**只升不降**。
  没有它就会漏：判定表只看标签、看不到字段，`clitoris`（阴蒂）、`after sex`（事后余韵）、
  `red velvet` 这类词不在表里 → 判 0 档 → SFW 档把它们抽出来。
- **逐选项上抬**（v3.8.0 新增）：`anima_v4_overrides.LEVEL_RAISE`，**只升不降**，
  精确到 (字段, 选项) 且必须写理由。补的是"判定表**没收录**这个词"的盲区 ——
  例如第一人称视角扩展词条里的 `pov crotch`（判定表只认 `crotch cut`，单写 `crotch` 判 0）、
  `pov breasts` / `pov legs`。没有它，SFW 档会把「第一人称下体视角」抽出来。
  ⚠️ 能被判定表正确判定的**不要**登记在这里（如 `pov, fellatio` 由 `fellatio` 直接判 3 档）。
- **人工校准下调**：`anima_v4_overrides.LEVEL_DEMOTE`，**只降不升**，同样精确到
  (字段, 选项) 且必须写理由。目前只有 2 条（`wet hair` 系列：判定表的 `^wet `
  模式本意是抓 `wet clothes`，在「头发」段属于误命中）。

> ⚠️ 两张校准表的 (字段, 选项) 集合**不相交**，且有基线钉住
> （`tests/check_v3_repair.py` ⑥）；选项原文写错字段名会**静默失效**，也在同一处钉住。
>
> ⚠️ 哪一条在哪个档位能用，面板上按**段内是否还有 ≤ 当前档的选项**判定 ——
> 不用「段最高档」判。后者在段里混入分档词条后会误标（v3.8.0 给「视角」加了
> `pov crotch`(L2)、`pov, fellatio`(L3) 之后，⑧镜头段最高档被抬到 3，
> 全年龄档就会被打上「本档不参与」，而该段 16 条全年龄词条照样在抽）。

## 五、三层权重

面板「设置 · 权重调节」区就是干这个的。数值范围 `0 – 3`：

| 层级 | 0 | 1.0（默认） | 3.0 | 中间值 |
|---|---|---|---|---|
| **段权重** | 整段关闭 | 正常 | 概率 ×3 | 相对倾向 |
| **字段权重** | 该字段永不出现 | 正常 | **必定出现** | 相对倾向 |
| **选项权重** | 该选项永不出现 | 正常 | **必定出现**（v4.1.1+；人物特征在有角色时让路） | 相对倾向 |

抽取概率：`p = clamp(基准概率 × 密度系数 × 段权重 × 字段权重, 0, 1)`

**「让某条选项一定有」的两种写法**：

- **点选项**（推荐，v4.1.1+）：在该选项的 🎯 细则里给 `3.0`，这一项必现
  （同字段多个 3.0 → 只在这几项里挑）。**人物特征**（发色 / 瞳色 / 体型 / 肤色 /
  脸型 / 发型四项）在**有角色时**让路给角色官方设定；其余字段（情绪 / 嘴部 /
  眼神 / 姿势 / 场景 / 服装 / 指甲 …）**勾不勾「不指定角色」都必现**。
- **点字段**：把该字段权重拉到 `3.0`（字段必现，选项仍随机），
  再在同字段的 🎯 细则里把其它选项设为 `0`。

**表情的特殊规则**（v4.2.0）：场景搭配会写死表情（`emotion` / `mouth` / `eye_gaze`），
按**场景档位**分治 —— `L0~L1` 场景里**权重说了算**（点哭泣就哭）；
`L2 及以上`场景**场景优先**（成人向正戏的表情与动作绑死，改成哭会毁掉场景立意），
报告会写 `场景表情优先（L3 场景）→ 权重点名的 哭泣 已让路`。

三条硬规矩：

1. **权重不拆档位闸门，但会「抬档」**（v4.3.0）。超档项本身不会被塞进低档候选池；
   点名（`3.0`）了越档词时，**整张图的档位自动抬到该词的档位**再抽（只升不降），
   报告写 `档位按点名词条自动上调：L2 成人 → L3 过激`。
   只对「姿势 / 体位 / 主题」这 10 个字段生效（发色 / 服装的 3.0 不会把 SFW 图抬成 extreme）。
2. **权重 0 是强指令**。角色的官方发色对齐、法典场景填充都必须让路 ——
   否则用户看到的是「我明明关了，它还是出来了」。
3. **密度自适应会整体缩放基准概率**，但字段权重 3.0 短路成必抽、不受影响。
4. **调过权重的字段默认必抽**（v4.3.0）。字段里有任一项 `≠1.0` 且 `>0` 时，
   该字段不再被 `base_prob` 整段跳过 —— 否则 `2.0` 与 `0.5` 的差别会被
   「字段这一轮没抽」稀释成噪声，用户看到的是「中间值没用」。
5. **点名 3.0 → 本次不自动套场景**（v4.3.0）。姿势 / 体位 / 主题任一项 `3.0`
   且用户**没有自己点场景**时，引擎不自动抽场景（自动场景的人数锁定 / 闭麦 /
   写死值会覆盖点名项）。手动套用的场景照常生效，但被点名的字段仍然让路；
   中间值（如 `2.0`）**不触发**排除，场景覆盖该字段时报告会写
   `情绪 由场景决定（选项权重本次未参与）`。
6. **复杂动作 / 主题会自动补一句自然语言**（v4.4.0）。`n_act` / `n_theme` 里的词条被点名
   `3.0` 且抽中时，引擎从 `presets/term_hints.json` 取一句话拼到正文结尾。实测这能把
   `irrumatio`（原来画成水下游泳）、`facesitting`（樱花街拍照）、`double penetration`
   （双女自拍）这类「只给 tag 画不出来」的词条救活 —— 同一批 15 条从严格一致 0/15 到 10/15。
   想给自己常用的词条加补充，直接编辑那个 JSON（**改完必须重启**）。
   写句子要整句、主谓宾清楚、带物理细节；**句内别用逗号**（会被 `collect()` 拆成 tag 堆），用句号分句。

权重表存在节点控件 `weights_json` 里（跟着工作流走），格式：

```json
{
  "sections": {"hair": 0},
  "fields": {"hair_color": 3.0, "outfit": 0},
  "options": {"hair_color": {"white hair": 1, "black hair": 0}}
}
```

只写想调的部分即可。空串 / 非法 JSON / 类型不对 → 一律当默认，**不报错**；
但引用了不存在的段/字段/选项时会在报告里给告警（不报错是为了老工作流能跑，
给告警是为了用户知道权重没生效）。

## 六、随机规则

- **必填字段**永远抽；其余按基准概率抽（面板可调，默认 0.65，源脚本是写死的）。
- **🔒 锁定**：`lock_fields` 里的字段不参与随机，由上游给值。
- **互斥消解**：12 条 sanitize（全裸 × 具体服装、连裤袜 × 赤足、蒙眼 × 眼镜/心形瞳、
  背对 × 注视镜头、POV × 全身、低画质设备 × 专业景深、俯拍 × 向上看…）
  ＋ 6 组正则互斥。每条被清掉的都会写进报告，不静默。
- **标签数**：按人数取上限（单人 29 / 双人 37 / 复杂 45，来自源脚本），
  但**不是抽完硬削** —— 而是用**二分法调密度重抽**，让落点尽量进自检的合格区间。
  源脚本固定从 8 个软字段里删，实测一次能删掉 13 个字段（发型/脸型/气质全没），
  画面特色被削平而且自检照样红。
- **确定性**：`seed >= 0` 时逐字节可复现；派生种子一律走 `zlib.crc32`，
  **不用内置 `hash()`**（后者每进程加盐，可复现就成了空话）。
- **成品检查 + 自动修复**（v3.8.0，`repair()`）：`sanitize()` 看的是**字段**，
  管不到"绕过字段"的内容 —— 手写补句 `extra_body`、法典预设自带的 `n_extra`、
  锁定/强制指定的值、上游拼接台送进来的文本。`repair()` 看的是**成品标签串**，专治这一类：
  ① 超档标签剔除（已登记校准项除外）；② 六组结构互斥（数量/视角/眼罩/服装/设备景深/体位）；
  ③ 下划线归一 + 去重。修了什么都会写进报告（面板与 `report['repaired']` 都看得到）。
  ⚠️ 刻意**不修**：超长且不在词库内的标签（可能正是你手写的作品名）、标签数量（该调密度或上限）。
  ⚠️ 正常生成的正文**零改动**（`tests/check_v3_repair.py` 用 200 个样本钉住）——
  它是安全网，不是"顺手改用户内容"。
- **槽位序输出**：按 ANIMA3 v3.0 规范重排
  （人数 → 角色 → 外观 → 服装 → 姿势 → 表情 → 镜头 → 场景 → 光影 → 细节 → 自然语言），
  而不是按界面段序 —— 界面段序会把「服装状态」排在「场景」之后，进 CLIP 的顺序是错的。
- **自检 17 条致命项 + 10 条风格项**：标签数量 / 禁词 / 画师名 / 重复 / 人数一致性 /
  视角互斥 / 眼罩互斥 / 服装互斥 / 角色完整性 / 标签长度 / 标签格式 / 体位姿态 /
  **档位准入** / 槽位映射 / **判档一致性** …
  同一套判据也开放给第 4 个节点「Anima 提示词检查与修复（V5）」，
  可以对**任意**提示词（不只本插件生成的）跑一遍并自动修。

## 七、典型使用示例

下面六个例子按「从最小到最实用」排列。每个都写了 **目的 / 步骤 / 关键点**。

### 例 1 · 最小跑通（不出图，30 秒）

**目的**：确认插件本身能跑，不牵扯模型和工作流。

**步骤**
1. 双击画布空白 → 搜 `Anima` → 拖入「Anima 提示词随机生成（V6）」。
2. 什么都不接，直接 `Queue`。
3. 看三个输出：`text` 是一串标签；`report` 里全是 ✅；`cn_summary` 是中文摘要。

**关键点**：这一步**不加载任何模型**。如果它跑不出东西，问题一定在插件，不在模型。

---

### 例 2 · 接进已有出图链路（不改一根线）

**目的**：把你手写的全局正文换成随机生成，其余流程原样。

**步骤**
1. 打开你平时用的 Anima 出图工作流。
2. 拖入「Anima 提示词随机生成（V6）」。
3. 把它的 `text` 输出，连到 **CR Text 节点（节点 1004，全局正文）那个空着的 `text` 输入端口**。
4. `Queue`。

**关键点**：那个端口**本来就在、且是空的**，所以不用改任何既有连线。拔掉线就回到手写文本框，
两套可以随时切换。接上之后，六条底模流会自动全部吃到这段正文。

---

### 例 3 · 双女 + 指定两个角色

**目的**：画面里明确要两个不同角色，且不要随机换人。

**步骤**
1. 打开面板 → 「角色库」页签 → 用搜索框找角色 → 勾选两个。
2. 回节点，确认 `selected_roles` 已同步（存的是 `tag`，如 `raiden shogun, genshin impact`）。
3. `seed` 设成固定正整数（`>=0`），这样每次跑都是这两个。
4. 跑一次 `/roll` 预演看报告。

**关键点**
- 勾了两个角色 → 人数标签自动联动成双人，不需要手写 `2girls`。
- `duo_role_fill`（v6.6.0 起**默认开**）会在人数不够时自动补位；关掉它，
  抽到的人数多于你勾的角位数时，**同一个角色会被复制成两个**（这是最容易踩的坑）。
- 要复现同一批量，`seed` 必须固定 —— `-1` 是每次重抽。

---

### 例 4 · 复现某一批图（seed + 权重表）

**目的**：这一批 20 张要同一个风格基调，只换动作。

**步骤**
1. 先把 `weights_json` 写好（面板调完点「采用」会自动写回这个字段）。
2. `seed` 设为固定值，跑一次，把 `text` 存下来。
3. 要换动作时，只改 `seed`，别动 `weights_json`。

**关键点**
- `weights_json` 跟着工作流走（是节点控件），换机器复制工作流时权重不会丢。
- ⚠️ 光靠 `seed` 不一定能复现 —— **服务端全局状态也参与抽取**，包括：
  服装库当前启用的那一套、角色预设覆盖、场景覆盖、收藏、角色自定义编辑。
  复现前先确认这些跟当初一致（见 [八、常见问题 FAQ](#八常见问题-faq) 第 9 条）。

---

### 例 5 · 每张图自动换一个场景（不用手点）

**目的**：批量 50 张，每张换一个姿势 / 艺术构图 / 特写场景。

**步骤**
1. 面板 → 「🧘 姿势库」/「🎨 艺术构图」/「🔍 特写搭配」任选一页。
2. 勾选若干条（或 `☑ 全选` / `⇄ 反选` 批量勾）。
3. 勾上工具条上的「**每次运行自动随机**」。
4. `seed = -1`，连跑。

**关键点**
- 三组开关**互斥**：同时只允许一组生效，开了另一组会关掉前一组。
- 与「🎬 随机抽取场景搭配」同时开时，**勾选池优先**（它是更明确的指令）。
- 抽中的那条**不回写面板**（面板仍显示你勾的那批），只在 `report` 里说明这次用了哪条。
- 放了超档场景时会**只升不降**地把档位抬上去，不会出现"抽到了又被闸门拦掉"。

---

### 例 6 · 用「检查与修复」收拾一段任意提示词

**目的**：手里有一段别处来的提示词，想知道它落在几档、有没有结构矛盾。

**步骤**
1. 拖入「Anima 提示词检查与修复（V6）」。
2. `text` 接任意字符串来源，`level` 选目标档位，`auto_fix` 保持 `True`。
3. 看 `report`（检查 + 修复明细）和 `num`（实际落档）。

**关键点**：它不只服务本插件生成的正文 —— 任意提示词都能过一遍。
⚠️ 它**不修**两类东西：超长且不在词库内的标签（可能正是你手写的作品名）、
标签数量（那该去调 `tag_cap` 或 `base_prob`）。

## 八、常见问题 FAQ

### 安装与启动

**1. 重启后节点列表里搜不到「Anima 提示词随机生成（V6）」？**
先看控制台启动日志有没有报错。最常见的三个原因：
① 目录名被改过（`tests/_boot.py` 里的包名是写死的，前端脚本名也不匹配）；
② 目录套了一层 —— 变成 `custom_nodes/Comfyui-Anima-Wardrobe-V6/Comfyui-Anima-Wardrobe-V6/`；
③ 和其他 Anima 系列插件撞了类名（正常不会，V6/V5/V4/V3 的类名与路由都是分开命的）。

**2. 节点能加进画布，但面板打不开（点了没反应）？**
面板是 `js/anima_wardrobe_v4_studio.js` 注入的，先确认这个文件在。
再开浏览器 F12 看控制台 —— 脚本语法错误会让整块面板静默失败。
⚠️ 改前端时有个经典坑：**CSS 写在 `const CSS = \`...\`` 模板字符串里，
注释里出现反引号会直接 `SyntaxError`**。

**3. 需要装依赖吗？`requirements.txt` 在哪？**
没有依赖，也没有 `requirements.txt` —— 纯 Python 标准库 + 原生前端 JS。
唯一的例外是 `tools/fetch_character_thumbs.py`（转 webp 要 Pillow），那**必须**用
ComfyUI 自带的 `python_embeded` 跑，系统 Python 通常没装 Pillow。

**4. 角色库里全是首字母色块，没有头像？**
缩略图是随仓库分发的（2432 张 / 29 MB），所以正常 clone 下来就有。
缺图只可能是：① 用了 `--depth` 浅克隆；② 手动删过 `presets/thumbs/`；
③ 你自己新增的角色还没有图。三种都用
`tools/fetch_character_thumbs.py` 补（见 [1.5 数据文件](#15-数据文件哪些随仓库哪些本机生成)）。

**5. 能和 `Comfyui-Anima-Wardrobe`（造型台 v2.x）同时装吗？**
能。类名、节点分类、HTTP 路由全部分开命名，互不干扰。

**6. 打开老工作流提示 `Required input is missing`？**
说明工作流比插件旧、或插件比工作流旧。V6 的所有新增控件都放在
`INPUT_TYPES["optional"]` **末尾**（这是硬纪律：放 `required` 会让老工作流整张输出被丢弃）。
如果还是报，用 `tools/` 下的迁移脚本按版本处理：`fix_workflows_v301.py` /
`fix_workflows_v302.py` / `fix_workflows_v303.py` / `fix_workflows_v3190.py`，**都先加 `--dry` 看计划**再落盘。

---

### 结果不符合预期

**7. 档位选了 `sfw`，为什么还是出现擦边内容？**
先看 `report` 里的实际档位。已知的一处系统性偏差：**湿发**。
判定表的 `^wet ` 模式本意是抓 `wet clothes`，对「头发」段属误命中，
本插件用降级白名单把它放回 0 档（让 SFW 能用湿发），代价是约 **19% 的 SFW 输出**
被造型台判成 2 档。根因在判定表本身，不是本插件的闸门漏了。

**8. 抽出来的角色不是我勾的？**
两个入口容易混：
- `selected_roles`（面板勾选）存的是 **tag**（如 `raiden shogun`）；
- `force_role`（手填）存的是 **trigger 串**。
改了某个内置角色的 trigger，老工作流里手填的那串就会失配 ——
**「已选角色」不受影响**（它存 tag）。

**9. 同一个 `seed`，两次结果不一样？**
`seed` 只保证引擎内部的随机序列，**服务端全局状态也参与抽取**：服装库当前启用的那一套、
角色预设覆盖、场景覆盖、角色自定义编辑、收藏。这些都不在节点输入里，
所以按输入 hash 复用旧输出时可能拿到上一次的结果。
节点用 `IS_CHANGED` 盯了 6 份状态文件的 `mtime_ns + size`，改数据会触发重算；
但**改了代码必须重启 ComfyUI**（没有热重载）。
临时绕过：在 `weights_json` 末尾补个空格，让输入 hash 变化。

**10. 面板里调了权重，出图没变化？**
两个可能：① 调完没点「采用」；② 权重点名了越档词条 → 档位被自动**抬上去**了。
`3.0` 只对「姿势 / 体位 / 主题」这 10 个字段抬档，发色和服装的 `3.0` 不会把 SFW 图抬成 extreme。
报告里会写 `档位按点名词条自动上调：L2 → L3`。

**11. 标签数总是不对，要么太短要么超长？**
`tag_cap` 设 `自动` 时按人数取上限（单人 29 / 双人 37 / 复杂 45，沿用源脚本）。
它不是"抽完硬削" —— 超了是用**二分法调密度重抽**，让落点进自检的合格区间。
固定削尾会一次删掉十几个字段（发型/脸型/气质全没），画面特色被削平。

**12. 双女场景里出现两个一模一样的角色？**
`duo_role_fill` 被关掉了。v6.6.0 起默认开，作用是在人数不够时自动补位
（同作品优先 → 单角色 IP 回退全库）。关掉后，人数多于角位数时就会复制同一个角色 ——
这是刻意的行为（尊重用户显式设置），不是 bug。

**13. 套用场景后，发型 / 服装被改了？**
场景预设会**写死**它声明的字段（`place` / `weather` / 服装 / 表情等），
这些字段让路是设计如此。想"固定地点但随机天气"，就选一个没写 `weather` 的场景 ——
随机只作用于预设**没写**的字段。
另外表情有分治规则：`L0~L1` 场景里权重说了算；`L2 及以上`场景**场景优先**
（成人向正戏的表情与动作绑死，改成哭会毁掉场景立意）。

**14. 「🔍 特写搭配」那页的条目怎么抽不到？**
特写是 `manual_only`（不进随机池），只能**显式套用**或放进勾选池。
这是刻意的：特写会清掉一批段和字段（收紧取景），自动抽到会让人莫名其妙丢掉构图。

**15. 出图元数据里没有 LoRA 触发词？**
是的。触发词由 LoraManager 在运行时计算，插件无从得知，所以**不打进元数据**。
这是有意的取舍 —— 宁可少一段，也不编一段假的。原始正文另有
`anima_v4_prompt` 块的 `positive` 字段可对照。

**16. 看图工具读不到提示词？**
插件把三类落点（工作流 widget / 自定义键 / 兜底位）都写全了，但
**读哪一份由看图工具自己决定**。若某个工具仍读不到，得拿它的解析逻辑单独适配。

### 参数与概念

**17. 「三层权重」到底三层是什么？**
段（整个段落）、字段（某个维度）、选项（某个具体取值）。三层是**相乘**关系，
不是覆盖关系。详见 [五、三层权重](#五三层权重)。

**18. 权重 `0` 和 `3.0` 有什么区别？**
`0` = **强指令**，该段/字段/选项永不出现，连角色官方设定都要让路；
`3.0` = 必现（同一个字段有多个 `3.0` 时只在这几项里挑）。
中间值（如 `2.0` / `0.5`）是相对倾向，靠概率加权，不保证。

**19. `base_prob` 和字段权重打架吗？**
不打架。`base_prob` 是"这个字段要不要抽"的基准概率；
字段权重 `3.0` 会短路成必抽，不受 `base_prob` 影响。
另外 v4.3.0 起：**字段里有任一项权重 `≠1.0` 且 `>0`，该字段默认必抽** ——
否则 `2.0` 和 `0.5` 的差别会被"这轮没抽这个字段"稀释成噪声。

**20. `disabled_sections` 怎么填？**
填段 id，逗号分隔。段 id 可以在面板权重树的段标题上看到，
或 `GET /anima-wardrobe-v6/contract` 拿全部段。

**21. `lock_fields` 和 `force_role` 有什么区别？**
`lock_fields` 锁**字段**（不让它参与随机，由上游给值）；
`force_role` 指定**角色**（填 trigger 串）。两个可以同时用。

**22. 发型四项 `hair_*_pick` 和 `hair_follow` 什么关系？**
`hair_follow` 是总开关（是否按角色官方发型对齐）；
四项 `hair_len/tie/curl/acc_pick` 是对齐的**分项覆盖**，默认都是「角色标签发型」= 跟随角色。
想强制换成自己的，只改对应的那一项即可。

**23. `dry_skin_filter` 三个参数怎么用？**
`dry_skin_tags` 是**唯一真值**（前端 19 条逐条复选框），语义是：
- `"all"` → 全关掉（所有水珠类词条都不出现）
- `"none"` → 显式一条都不关
- `"t1,t2,t3"` → 只关这几个 tag
- **空串** → 回落到 `dry_skin_groups` 的组语义（老工作流零回归）
`only_tags` 优先于组。

**24. `pick_pool_mode` / `pick_pool_ids` 要手填吗？**
不用。这两个是面板复选框回写的**结果**（`mode` 只为报告与三组互斥服务，
`ids` 是抽选范围）。手工填也能生效，但面板一勾就会被覆盖。

### 性能与批量

**25. 一次抽取要多久？**
纯 Python 计算，不涉及模型，单次在毫秒级。感觉到"慢"通常是面板首次拉
`/characters`（约 928 KB）或 `/pools`（含中文名与逐项档位）的网络耗时。

**26. 批量跑几百张，有什么要注意的？**
⚠️ **服装库的"启用"是全局状态**，不是节点参数。批量跑之前确认当前启用的那一套是不是你要的
（`lv < level` 的套装整套不生效，扫图要按每套自己的档位跑）。
同理，勾选池、场景覆盖、角色预设覆盖也都是全局态。

**27. 一套服装库启用后，随机服装全没了？**
服装库是**整套闸门**：启用一套就闭麦 13 个服装字段，随机服装不再参与。
优先级是 **角色预设 > 服装库 > 随机**。角色启用但档位不够时会**留空**，不会回落到随机。

**28. 会联网吗？会上传内容吗？**
运行时不联网、不上传任何东西，全部在本机完成。
（建角色库 / 抓缩略图这两个 `tools/` 脚本是开发期用的，会联网，但**不是运行时路径**。）

**29. 能商用吗？**
代码层面是 GPL-3.0。但**生成内容的合规性**由你自己负责 ——
请确认符合所在地区法律法规、所用模型的使用条款、发布平台的政策。
角色名 / 作品名的知识产权归各自权利人。

**30. 为什么 NSFW 分五档而不是一个开关？**
一刀切的"开/关"没法表达"擦边"。五档是逐级放开**段落**：
低档先从候选池里排除，不是抽完再筛 —— 后者会用"抽完打补丁"的方式把高档内容漏进低档。
详见 [四、NSFW 分级标准](#四nsfw-分级标准核心)。

## 九、注意事项与限制

前半是**硬限制与已知偏差**（用之前该知道的），后半是待办。

- **`wet hair` 的两难**：判定表的 `^wet ` 模式会把「湿发」判成 2 档。
  本插件用降级白名单把它放回 0 档（SFW 可用湿发），代价是约 19% 的 SFW 输出
  被造型台的 `grade_nsfw` 判成 2 档。**根因在判定表本身**，建议后续把
  `^wet ` 收窄成 `^wet (clothes|shirt|dress|...)`，改完重跑 `sync_nsfw_tables.py` 即可。
- `n_exposure / presenting`（翘臀展示）被判定表归进「性行为」分类 → 3 档。
  同一字段里其它 9 个选项都是 2 档，口径偏严。**未擅自降级**，留给用户决定。
- 源脚本 `face/eyes_color` 里「异色瞳」写了两遍（同一个 danbooru tag 出现两次），
  属源脚本小瑕疵，未擅自改（改了会破坏零漂移对拍）。
- 面板的「本段随机」目前只在后端支持，面板 UI 尚未挂按钮。
- **角色库中文名覆盖率 61%**：能自动提取的（wiki 别名里带中文的）已全部提取，
  剩下 39% 在 danbooru wiki 上确实没有中文别名，显示英文原名。
  想再提高需要手工补一张 `tag → 中文名` 表。
- **角色库不含男性，但可能有漏网**：性别判定优先级是
  「造型台全量性别表 > 官方特征 tags > wiki 代词 > 默认女性」。
  零人气（safebooru 上一条投稿都没有）**且没有任何女性佐证**的条目已剔除 105 条，
  但仍可能有边界情况；`tests/check_v3_chars.py` 会持续盯这条。
- **换装变体一并收录**：`asuna_(bunny)_(blue_archive)` 这类是独立的 danbooru
  角色 tag，在浏览器里作为不同的「造型版本」出现 —— 这是特性不是脏数据。
- **缩略图覆盖率 100%**：2432 张图与 2432 位角色**一一对应**，没有遗留、没有缺口。
  想自己重生成（换模型或换画风）：跑 `tools/make_new_char_thumbs.py` 那套裁切流程。
  （**可中断可续跑**，每次跑都会先自愈清掉尺寸过小的坏图）。
- ⚠️ 抓图脚本必须用 **ComfyUI 内嵌的 Python**（`python_embeded`）—— 转 webp 依赖
  Pillow，系统 Python 里通常没有。
- **自定义角色没有发色 / 瞳色**（v3.4.0 的编辑弹窗刻意不暴露这两个字段）→
  `appearance_follow` 对它们会跳过对齐，不会报错，只是不强制发色瞳色。
  想补可以手改 `presets/user_characters.json` 里的 `hair` / `eyes`。
- **特征标签在引擎里只有两处被用到**（体型 + 兜底发色瞳色，见 [四、角色编辑与自定义角色](OVERVIEW.md#四角色编辑与自定义角色v340)）——
  改别的标签在当前版本不会影响出图，但会如实存下来（数据保真），
  将来引擎扩了用途就自动生效。
- ⚠️ **列表载荷的 `tags` 只带前 8 条**（卡片展示用）—— 想拿全量走
  `GET /characters/detail?tag=`。任何"想读全部标签"的新功能都别指望列表接口。
- **元数据里的"完整正向"是尽力还原**：`该流质量词 + 插件正文`。中间那段 **LoRA 触发词**
  由 LoraManager 运行时计算，插件无从得知，所以**不会出现在元数据里**（这是有意的取舍：
  宁可少一段，也不编一段假的）。原始正文另有 `anima_v4_prompt` 块的 `positive` 字段可对照。
- **兜底位填的是"正文原值"**，而那些位置运行时的真值由第三方给（如触发词）——
  本模块**只填空位**，绝不覆盖任何已有字面量；这些位置在 ComfyUI 界面里由插槽接管，不显示控件值。
- 看图工具读哪一份元数据（`workflow` 的哪个 widget、还是自定义键）由它自己决定，
  本插件把三类落点都写全以兼容；若某个工具仍读不到，需要拿它的解析逻辑单独适配。
- ⚠️ **手填角色（`force_role`）存的是 trigger 串** → 改过 trigger 的内置角色，
  老工作流里手填的那串会失配（**「已选角色」不受影响** —— 它存的是 tag）。
- ⚠️ **「视角」字段现在是分档字段**（v3.8.0）：段内混有 L0（`fisheye` 等）、
  L1（`pov breasts` / `pov legs`）、L2（`pov crotch`）、L3（`pov, fellatio` 等）。
  低档下这些高档选项**不会进入候选池**，面板上它们仍会列出来（标着 `L2` / `L3`），
  这是有意为之 —— 让你看得见"开高档能抽到什么"。段标题的「本档不参与」
  按"段内是否还有 ≤ 当前档的选项"判定，不会因为该段有高档选项就误标。
- ⚠️ **`first-person view` 这个标签在 danbooru 上并不存在**（源脚本原来就这么写，
  已与 `pov` 组合使用）。为了守住"词库零漂移"这条纪律**刻意保留原样**；
  真正起作用的是 `pov` 本身（danbooru 20 万+ 投稿）。新增的第一人称词条都用了
  真实存在的标签（已按 safebooru 的 `post_count` 逐个核对）。
- **`LEVEL_RAISE` 只覆盖判定表的盲区**，不是"我觉得该判几档"。
  能被判定表正确判定的（如 `pov, fellatio` 由 `fellatio` 判 3 档）**不重复登记** ——
  重复登记会让"判定表真源在造型台"这条纪律名存实亡。
- **场景搭配库目前 87 条**，档位分布 L0=32 · L1=2 · L2=8 · L3=36 · L4=9。
  ⚠️ **挖矿类（原自慰）做不出 L1**：擦边档不允许任何露出标签，而自慰的展示/行为标签
  （`n_state`/`n_exposure`/`n_body` 全部 L2、`n_act` 自慰项 L3、`squirting` L4）
  —— 硬凑一个 L1 版本只能写「脸红夹腿」这种暗示，不算自慰，所以不做。
  ⚠️ **L1 / L2 偏少**（各 2 条）：擦边与成人档的「整套搭配」本身不多 —— 擦边的露出主要靠
  ⑥ 段的微距泳装 / 露肩这类**单字段**内容，硬凑成一整套场景反而别扭。想要更多就往 JSON 里加，
  跑一次 `tools/build_scenes.py` 会自动判档。
- 以下为 v3.9.0 时的规模（已过期，留作对照）：
  文档 §14 的十二类配方已全部覆盖，但每类只做 1–2 条代表搭配 ——
  想再细化（比如 NTR 的电话/窗外/分屏各一条）直接往 JSON 里加，跑一次
  `tools/build_scenes.py` 即可，档位会自动派生。
- **场景搭配的"固定"是字段级**：预设写死 `place` / `weather` 这些**整字段**。
  同一个字段里想"半固定"（比如固定地点但随机天气）就不写那个字段即可 ——
  随机只作用于预设没写的字段。**没有**"字段内部分选项固定"的机制，也不需要。
