# 评估：能否把 Comfyui-K2-Editorial 的预设场景并入 Anima 场景库

> 评估时间：2026-11-13 04:5x｜对象：`custom_nodes/Comfyui-K2-Editorial/presets/*`
> 结论：**能读，但不能直接当"场景预设"并入** —— 两者不是同一种东西；有三条可行路线，推荐 B。

---

## 1. K2 的"预设场景"到底是什么

K2-Editorial 没有"场景"这个概念，它的对应物是**母题（motif）**，共 **303 条**（另 321 条有中文名）：

| 文件 | 内容 | 规模 |
|---|---|---|
| `manifest.json` | 面板数据层：id / title / zh / aspect / tags / branch / thumb | 303 条 |
| `seeds_motifs.json` | 从 `MIKU-未来科幻风格` 抽取的母题，21 段结构化 | 32 条 |
| `seeds_extra.json` | 人工新写母题 | 271 条 |
| `motif_tags.json` | 粗分类标签 | 64 条 / 10 种标签 |
| `motif_aspects.json` | 画幅人工改判表 | 极少 |
| `motif_names_zh.json` | 中文名 | 321 条 |

单条母题的形态（`seeds_extra` 样例）：

> **k2p_arashi｜あらし｜岚｜1490 词**
> "Create a horizontal 16:9 full-bleed flat graphic design poster titled "あらし",
> themed as a nocturnal storm observatory converting wind, rain, pressure, and sound
> into one editorial graphic system. Use the exact Japanese hiragana title…"

分支分布：`scene` 183 / `short` 105 / `poster` 15；画幅：横 194 / 竖 96 / 方 12 / 通用 1。
每条都带中文名与缩略图（`thumbs/motifs/*.webp`）。

---

## 2. 为什么不能直接搬进 Anima

| 维度 | K2 母题 | Anima 场景预设 | 冲突程度 |
|---|---|---|---|
| 形态 | 800–1800 词、21 段长文 | `tags` 字段字典 + 40–80 词 `scene_nl` | **致命** |
| 内容 | 平面设计海报 / 版式 / 印刷质感 / 画面内标题文字 | 人物姿势 + 镜头 + 光影 + 地点 | **致命** |
| 语义域 | 虚构设计场景（玻璃水槽剖面、风观测站、白垩光） | 日常地点（卧室/教室/电梯/厨房） | 高 |
| 标签粒度 | 10 种粗标签（day/night/interior/architecture…） | 61 个 place + 20 light_fx + 21 weather | 高 |
| 档位 | 无 NSFW 档位 / 人数 / 闭麦概念 | level 由内容派生、参与闸门与随机池 | **致命** |
| 标题 | `title` 是要**画进画面**的文字（"STILL SECTION"） | 场景不含画面文字 | 高 |

补充实测：271 条 K2 长文里，Anima 的 61 个 `place` 选项有 41 个出现过，但这是"全文里出现过某词"，
不是"这条母题就是这个地点"——真正的 per-motif 映射覆盖率远低于此。

---

## 3. 三条可行路线

### A. 抽取式（把母题降维成 Anima 场景）
从长文里抽 `place` + `light_fx` + `weather` + 3–5 个 extra 标签，生成标准 Anima 场景。

- 产出：可进随机池、参与档位派生，与现有 612 条同构
- 成本：303 条 × 规则/LLM 抽取 + 人工抽检
- 风险：`scene` 分支（183 条）多为虚构设计场景，落到 Anima 61 个 place 的比例低；
  强行映射会产出"卧室 + 风观测站"这类错配

### B. 外挂式（推荐）
新增 `group=k2`、`manual_only=true`，每条只存 `{id, zh, title, aspect, thumb, raw}`；
套用时把 `raw` 整段走 **`extra_body`** 通道注入，不参与 tags / 档位 / 随机池。

- 改动面：`groups` 增加一项、`build_scenes` 校验放行、面板加一个页签、套用走 `extra_body`
- 数据成本：**零**（直接读 manifest + 复用 thumbs）
- 优点：不改现有 612 条任何行为，风险隔离；K2 母题成为"设计海报库"与场景库并存
- 风险：Anima 12B LoRA 对"海报版式"提示的响应未知，需 3–5 张真机验证

### C. 只读浏览器
不动数据，Anima 面板加"K2 母题"页签，缩略图 + 标题，点击把 `raw` 复制到 `extra_body` 输入框。

- 改动最小（纯前端），但每次要手动粘贴
- 适合"偶尔借用"而不是"沉淀进库"

---

## 4. 建议

1. 先做 **C** 验证一件事：把 3 条母题的 `raw` 直接塞进 Anima 的 `extra_body`，看画面是"人物写真"还是"海报"。
   - 如果出的是海报 → 说明 Anima 不适合承接 K2 母题，**B 也不必做**；
   - 如果人物仍在、只是加了版式元素 → 值得做 B。
2. 若只想要"更多地点"，走 **A**，但只挑 `branch=scene` 里确有日常地点的那部分（估计 30–60 条），
   不要全量硬映射。
3. 不建议把 303 条整段塞进 `scene_nl`：`collect()` 按逗号切分，长文会被拆成一堆伪标签，
   F11/repair 会连环报红，且模型响应不可控。

---

## 5. 需要你定的

- 目标是"**多一批地点/氛围**"（走 A）还是"**多一种海报画风**"（走 B/C）？
- 若走 B，是否允许新增 `group=k2`（会出现在场景面板里，但不进随机池）？

---

## 6. 真机验证（2026-11-13 04:5x）

用 3 条母题（`scene` 静谧切片 / `poster` 岚 / `short` 晨曦海报01）分别跑两个 Anima 工作流：

| 母题 | 12B（720×1280 / 8 步 / cfg1.4） | 29B 艺术构图（1280×720 / 16 步 / cfg2） |
|---|---|---|
| 静谧切片 | 初音站姿白底插画 | 水下场景 + 鱼群 + 光束 |
| 岚 | 初音侧脸特写、梦幻柔光 | 彩色飞溅、构图更"平"更设计感 |
| 晨曦海报01 | 兽耳角色持玻璃球 + 零散文字碎片 | 水下站立 + 画面内文字 `tidal sicel` |

### 结论

1. **两个工作流都不出"平面设计海报"** —— 母题里 `flat graphic design poster` / 网格版式 / 丝网印刷质感
   这些指令基本没被执行，出来的是**人物插画**。
2. **角色会被母题抢走**：正文里 `kanna` 与 `miku` 同时存在（6/6 张），
   视觉上 6 张里有 5 张画成了**初音未来** —— 母题长文里的
   "Hatsune Miku + canonical identity" 压过了角色 tag。
3. **标题文字会以乱码出现**（`tidal sicel`），29B 更明显（负向词里有 `text` 也压不住）。
4. **但母题的氛围元素确实被带出来了**：水下、鱼群、玻璃球、霓虹数据面板、彩色飞溅。
5. 29B 的"设计感"强于 12B，但两者都还是"人物图 + 氛围"，不是海报。

### 对三条路线的影响

| 路线 | 判定 |
|---|---|
| A 抽取式 | **成立且有价值** —— 可抽的是"水下/鱼群/玻璃球/数据面板"这类元素，落成 `extra` + `light_fx` + `weather` |
| B 外挂式（整段 raw 注入） | **不成立** —— 抢角色、乱码文字、不出海报，三点都不可接受 |
| C 只读浏览器 | 仍可用，但要先**剔掉 raw 里的角色名与标题**，否则每次都会被抢 |

### 若要继续，最小可行改动

抽取时先做三件事，再谈入库：
1. 删掉母题里的角色名（`Hatsune Miku` 等）与 `canonical identity` 段；
2. 删掉 `titled "…"` 这类画面内文字要求；
3. 只保留场景/材质/光/色彩关键词，降维成 8–15 个 Anima 能识别的 tag。
