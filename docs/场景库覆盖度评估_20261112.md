## 4. 明确不做（别补清单）

| 类别 | 原因 |
|---|---|
| 未用的多人 / 特定题材类选项 | 引擎在多人下会清空动作字段，历史实测服从度最低 |
| 未用的部分动作类选项 | 历史实测服从度差，其余为泛词，边际收益低 |
| 镜像 / 倒影类 | 会画出第二个身子，属画面红线 |
| 自身视角类 | 硬边界 |
| 给高档场景内置 `outfit` | 与「场景优先 + 服装库整套闸门」冲突；服装库应走推荐联动 |
| L4 扩容 / 多人题材 / 纯随机池扩容 | 边际收益最低，或稀释高档分布 |
| **P0-A 双人同框三铁律回填** | **21:36 用户明确取消**：现有「双人标签取语义、构图只拍单人」是刻意设计，反向套用会破坏意图；连 `count_lock` 都不要动 |

> ⚠ 曾把「34 条双人场景里关系句只 3 条、`wide shot` 2 条、13 项全闭麦 1 条」判成存量质量债 —— **这是误判，已作废**。双人正戏三铁律只适用于「要双人同框」的新场景，不适用于这批既有条目。

## 5. 已落地：v6.10.1 P0-B

- **手法**：给 17 条零随机维度场景各补 1 个 `random_fields`（emotion 6 / eye_gaze 6 / light_fx 2 / weather 3），候选沿用 v6.10.0 的全 L0 池。
- **硬断言**：不与 `tags` / `drop_fields` 同字段、候选合法、改前后 `scene_level()` 相等；备份 → 临时文件 → `os.replace` 原子替换。
- **结果**（22:0x 磁盘复核，与 21:40 备份对比）：

| 指标 | 21:40 备份（改前） | 现值 |

| 场景总数 / 档位 / 画幅 | 602 / 394-74-55-54-25 / 273-246-83 | **完全不变** |
