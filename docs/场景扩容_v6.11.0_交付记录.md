## 3. 踩坑与结论（下次直接引用）

1. **非多人场景的 L4 只有两个合法抬档标签**：`n_orgasm=squirting`、`n_theme=collar and leash`。
   `excessive cum` / `bukkake` / `multiple creampie` / `threesome` / `foursome` / `gangbang` 全在
   `GROUP_ONLY_TAGS`（`anima_v4_rules.py`），单人/一男一女写了会被引擎**静默丢弃**。
   首版第 6 条用 `n_cum=excessive cum` + `n_orgasm=mind break`，真机 positive 里两个都没了、
   被随机补成 `squirting` —— 典型的「条目挂 L4、运行时内容掉回 L3」半吊子状态。已改成 `squirting`。
2. **改完 presets 必须清缓存**：服务端 `_CACHE` 是进程级快照，`/anima-wardrobe-v6/health` 仍报 602 时，
   显式 `n_canon` 因场景 id 不在旧快照里被丢弃、静默回退成随机场景（首轮试跑就踩到）。
   清法：`POST /anima-wardrobe-v6/outfit-library/scene-override` 发**同值** `{"enabled": false}`。
3. **`place` 与 `count` 都不抬档**：`option_levels.place` 61 项全 0、`1girl, 1boy, hetero` 也是 0。
   所以地点可以精确落在目标档，档位只由内容标签决定 —— 加地点不会把档位带跑。
4. **`dry_skin_filter=True` 会滤掉 `glistening skin`**：第 8 条温泉的 `n_body=glistening skin`
   在该工作流里不出现，属工作流设定（皮肤干爽过滤），不是场景缺陷；换关闭过滤的工作流即出现。
5. **UI 冒烟的 BDSM 题材基线 18 → 19**：第 2 条 theme 写 `BDSM`，`av3_ui_smoke.mjs` 两处硬编码
   计数已同步改为 19（断言语义未变：筛选后只剩该题材）。
6. 服务端进程仍是 20:07 启动的旧快照，`/health` 报 6.9.4、PNG 元数据 version 报 6.10.0，
